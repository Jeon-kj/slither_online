# AI 활용 리뷰 문서 작성 가이드

리뷰 문서를 작성·수정하기 전에 이 가이드와 같은 폴더의
`2026-11-14-bot-disconnect.md`를 모두 읽는다.
참고본의 요청별 평가 방식과 구체성을 활용하되, 사건의 내용이나 결론을 다른 리뷰에 복사하지 않는다.

## 작성 원칙

- 사용자가 지정한 핵심 요청을 평가 단위로 삼는다. 이후 문서 수정이나 리뷰 대화로 범위를 넓히지 않는다.
- 각 요청에서 충분했던 점, 위임 범위와 의존도, 더 효율적인 활용 가능성을 평가한다.
  AI의 작업 결과나 실수 목록으로 사용자 활용 방식에 대한 평가를 대신하지 않는다.
- 실행을 넓게 맡겼다는 이유로 의존적이라고 판단하지 않는다.
  원인·성공 기준·변경 영향·결과 수용을 검토한 근거가 있는지 구분한다.
- 이미 충분한 요청은 충분하다고 적는다. 억지로 개선안을 만들거나,
  AI가 스스로 처리할 일을 사용자가 더 자세히 지시해야 했던 것처럼 평가하지 않는다.
- 개선안을 제시할 때는 정확성·효율·판단력·학습 중 무엇이 나아지는지 설명한다.
  뒤늦게 밝혀진 원인을 사용자가 처음부터 알고 요청했어야 한다고 요구하지 않는다.
- 사용자의 관찰·요청·판단과 AI의 분석·구현·검증을 구분한다.
  대화에 드러나지 않은 이해는 미확인으로 남기며, 이해 부족이나 무비판적 수용으로 단정하지 않는다.
- 요청은 글머리 목록으로 간결하게 요약하고, 평가는 이유가 연결되는 짧은 문단으로 작성한다.

## 필수 구성

- `## 전체 평가`: 사용자의 AI 활용 방식에 대한 전체 판단과 가장 중요한 개선 방향.
- `## 요청별 평가`: 핵심 요청마다 번호가 있는 하위 제목과 아래 구분 문구를 사용.
  - `**사용자 요청**`: 실제 요청의 간결한 요약.
  - `**평가**`: 충분했던 점과 위임 범위·의존도 판단 및 근거.
  - `**더 효율적인 활용**`: 유효한 개선안과 효과. 개선이 필요 없다면 그 사실을 간단히 명시.
- `## 결과 수용에 필요한 이해`: `**확인된 것**`과 `**확인되지 않은 것**`으로 구분.
  결과 수용에 중요한 이해만 다루며 학습 질문 목록으로 대체하지 않음.
- `## 다음 작업에 적용할 원칙`: 이번 평가에서 도출한 활용 원칙 하나.
- `## 검토 범위`: 평가 대상과 근거, 누락된 대화나 검증 한계가 있다면 간결하게 명시.

위 제목과 구분 문구는 실제 출력 문서에 유지하는 형식이다.
요청 수와 단계 제목은 검토 대상에 맞게 정한다.

## 문서 틀

```markdown
# 문제명에 대한 AI 활용 회고

## 전체 평가

사용자의 활용 방식과 핵심 개선 방향에 대한 짧은 평가.

## 요청별 평가

### 1. 핵심 요청 요약

**사용자 요청**

- 사용자가 실제 전달한 조건과 요청

**평가**

충분했던 점과 위임 범위·의존도에 대한 근거 있는 평가.

**더 효율적인 활용**

개선할 가치가 있는 행동과 그 효과, 또는 현재 요청으로 충분한 이유.

## 결과 수용에 필요한 이해

**확인된 것**

- 실제 대화에서 확인된 사용자 행동이나 판단

**확인되지 않은 것**

- 결과 수용에 중요하지만 확인되지 않은 이해

## 다음 작업에 적용할 원칙

다음 작업에 적용할 활용 원칙 하나.

## 검토 범위

평가 대상과 근거 및 한계.
```

## 작성 후 확인

- 핵심 요청 각각을 평가했으며, AI 작업 품질 회고로 바뀌지 않았는가?
- 필수 제목과 요청별 구분 문구를 유지했는가?
- 위임 범위와 의존도를 실제 사용자 행동에 근거해 판단했는가?
- 개선안을 위해 불필요한 사용자 작업이나 사전 지식을 요구하지 않았는가?
- 확인된 이해와 미확인 사항을 구분했는가?
- 지정된 검토 범위와 참고본의 기록 밀도를 유지했는가?
