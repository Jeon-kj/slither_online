# Slither Head 위치 적용 순서 조사 및 수정

## 배경과 요청

서버 실행 후 Unity 클라이언트에서 자기 Slither가 끊겨 보이며, 같은 화면의
봇은 상대적으로 부드럽게 보인다. Game 뷰뿐 아니라 Scene 뷰에서도 관찰된다.
사용자는 입력의 급격한 변화, 카메라, 부스트, 충돌 보고를 후보에서 제외했다.

이번 요청 프롬프트:
> 2번을 후보로 두고, 문제를 다시 탐색해봐. 추가로 발견되는 원인이 없으면 2번을 해결한 후 다시 검증해보자

여기서 2번은 `SlitherContext.SetHeadPos()`가 자식 Head를 먼저 옮긴 뒤
부모 루트를 옮기는 문제다.

## 재탐색 결과

- `SampleScene.unity`의 `SlitherManager`는 하나의 `Slither.prefab`을 참조한다.
- `InitSlither()`는 로컬과 원격 모두 같은 프리팹으로 생성한다.
- Head의 Kinematic Rigidbody2D, 보간 비활성 설정은 프리팹에 공통으로 존재한다.
- 로컬 분기는 입력 대상·카메라 대상 설정과 CollisionReporter 추가다.
- 수신 이후에는 ID에 관계없이 `HandlePos()` → dispatcher →
  `UpdateSlitherPos()` → `AppendSample()` → `SetHeadPos()`를 거친다.
- Assets의 C# 위치 대입·MovePosition·속도·Translate 검색에서 별도로
  Slither를 이동시키는 경로를 발견하지 못했다.

제외된 후보 외에 로컬/봇의 차이를 설명하는 추가 원인은 확인하지 못했다.
이 결과는 저장소의 씬과 코드에 대한 조사이며 실행 중 인스턴스 검사는 아니다.

## 원인과 수정

Head는 루트의 자식이다. 기존에는 Head의 월드 위치를 수신 좌표 P로 맞춘 뒤
루트도 P로 옮겼다. 따라서 Head에 루트 이동량이 추가된다.
이전 루트 위치가 R이면 함수 종료 후 Head 월드 위치는 `P + (P - R)`이다.

부모 루트를 먼저 옮긴 후 Head의 월드 위치를 P로 맞추도록 두 대입문의 순서만
바꿨다. 경로 샘플, 몸통 갱신, 패킷, 서버, 보간 방식은 변경하지 않았다.
몸통은 기존대로 `UpdateSlitherPos()`에서 각 경로 노드의 월드 좌표로 다시 배치된다.

이 오류는 모든 Slither에 공통이다. 특히 직선 등속 이동에서는 오차가 일정하므로
이 수정만으로 로컬의 끊김이 해결됐다고 판단할 수 없다.

## 검증

Unity 및 C# 컴파일러 실행 파일이 없어 Unity 컴파일, Rigidbody2D/물리 동기화,
프레임 시간, 실제 화면의 수정 전후 비교는 실행하지 못했다.
서버 코드는 변경하지 않았다.

대신 이전 조사에서 얻은 실제 서버 수신 좌표를 같은 조건으로 재생하여
수정 전후 부모/자식 좌표 대입을 수치 모델로 비교했다. 루트 회전 identity,
프리팹 루트 스케일 0.5, 초기 Head 로컬 위치 0을 사용했다.
이 검사는 Unity 런타임 테스트가 아니며 물리 시뮬레이션을 포함하지 않는다.

- 수신자 2개 × Slither 2개, 좌표열당 195~196개.
- 수정 전 Head와 수신 위치의 최대 거리: 약 0.026001.
- 수정 후 모델상 최대 거리: 0.
- 직진, 회전, 반전, 큰 이동, 음수 스폰, 동일 좌표의 직접 재적용 사례도 확인했다.
  실제 호출부는 동일 좌표를 `AppendSample()`에서 건너뛴다.
- `git diff --check` 통과.

재실행: `python3 /tmp/slither-head-position-check.py`

임시 원본 및 실행 파일(환경 정리 시 사라질 수 있음):

- `/tmp/slither-motion-probe.json`: 이전 서버 실험의 수신 좌표 원본.
- `/tmp/slither-head-position-check.py`: 소스의 대입 순서 검사 및 좌표 재생.
- `/tmp/slither-head-position-check.json`: 수정 전후 계산 결과.

## 에디터 재현 및 남은 확인

1. 기존과 같은 서버·Unity 씬·봇 수로 접속한다.
2. 클릭하지 않고 마우스를 고정한 기존 재현 조건에서 Scene 뷰의 자기 Slither와
   봇을 비교한다. 필요하면 별도 체크아웃의 수정 전 버전과 같은 조건으로 비교한다.
3. `SetHeadPos()` 종료 시 루트와 Head의 월드 위치가 모두 수신 좌표인지 확인한다.
   중단점은 좌표 확인에만 사용하고, 움직임 관찰 시에는 제거한다.
4. 직진 및 방향 변경에서 Head의 루트 상대 위치가 0으로 유지되는지 확인한다.
5. 끊김이 남으면 동일 MSG_POS의 로컬/봇 좌표와 실제 적용 좌표 및 프레임 시간을
   비교해야 한다. 보간 부재와 수신 큐 일괄 처리는 공통 구조로 남아 있으나,
   로컬만 더 끊기는 원인으로 확정하지 않는다.
