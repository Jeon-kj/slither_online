# 연결 종료 시 플레이어 제거 알림 누락 해결

## 문제 요약

정상 퇴장과 사망에는 제거 알림이 있지만, EOF와 통신 오류로 종료하면 다른 클라이언트에 제거 알림이 없었다.

### 문제 발생 조건

- 직접 검증: 소켓 상대 종료로 recv()가 0을 반환하거나 송신이 EPIPE로 실패하는 경우
- 직접 검증: 연결되지 않은 TCP 소켓의 ENOTCONN 수신 오류 분기
- 클라이언트 코드 확인: 위치 목록에서 빠진 플레이어를 자동 삭제하지 않고 MSG_PLAYER_LEFT에서 삭제하는 구조

## 원인 및 해결

제거 알림이 정상 퇴장·사망 호출부에만 있었다. 활성 연결의 공통 종료 함수에서 서버 ID로 제거 알림을 생성하도록 이동했다. 정상 퇴장의 처리 순서는 알림 예약 후 연결 정리에서 연결 정리 후 알림 예약으로 변경했다. 삭제된 연결을 수신 대상에서 제외하고 서버 상태와 알림을 함께 정리하기 위한 변경이다.

## 해결 과정

### 1. 분석과 재현

**사용자 요청**

- 종료 경로별 알림 누락의 실제 여부 재현과 원인·해결책 검토 요청
- TCP 연결 종료와 게임 객체 삭제의 코드 흐름 설명 요청

**결과**

- 정상 퇴장·사망의 제거 알림 1회와 EOF·송수신 오류의 알림 누락 확인
- 소켓 정리, 서버 상태 삭제, 다른 클라이언트의 객체 삭제가 별개임을 설명했음

### 2. 수정과 검증

**사용자 요청**

- 제시한 해결책 실행 요청

**결과**

- 공통 종료 함수로 활성 플레이어의 제거 알림 이동 및 기존 호출부의 중복 전송 제거
- 제거 알림의 수신 목록 복사와 송신 큐의 존재 검사로 알림 중 추가 연결 실패에 대비했음
- 입장 전 종료의 알림 생략과 중복 종료의 알림 중복 방지 확인

## 조언

- 연결 종료 원인별 검증과 별도로 알림 중 다른 연결이 실패하는 경우까지 확인할 필요가 있음. 송신 큐 등록도 epoll 실패로 연결 목록을 바꿀 수 있기 때문임.

## 변경 파일

| 파일 | 변경 내용 |
|---|---|
| server/server.cpp | 연결 정리만 하던 공통 경로에 활성 플레이어의 제거 알림을 추가했다. |
| server/message_handler.cpp | 정상 퇴장의 별도 제거 알림을 공통 종료 처리로 대체했다. |
| server/slither_manager.cpp | 사망의 별도 제거 알림을 공통 종료 처리로 대체했다. |
| server/message_sender.cpp | 제거 알림의 직접 연결 목록 순회를 복사본 순회로 변경했다. |
| server/utils.cpp | 송신 큐의 암묵적 연결 생성 접근을 존재 검사로 변경했다. |

## 확인 결과

- 기존 임시 재현 프로그램을 수정 코드에 재빌드해 정상 퇴장, EOF, EPIPE, ENOTCONN, 사망에서 제거 알림 1회 확인
- 입장 전 종료의 알림 0회, 중복 종료의 알림 1회, 알림 중 추가 epoll 실패의 연결·소켓 정리 확인
- 검증은 서버 함수와 소켓 및 관찰자 송신 큐 기준이며 Unity 화면과 실제 TCP RST는 미검증
- server/에서 make 실행은 Makefile 부재로 실패했으나 기존 CMake 설정의 서버 빌드 통과
- 사용자 게임 환경의 해결 확인은 아직 없음
