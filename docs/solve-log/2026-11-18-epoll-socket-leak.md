# epoll 실패 시 소켓 누수 해결

## 문제 요약

epoll 등록·변경 실패 시 서버 연결 정보만 삭제되고 소켓은 열린 채 남았다.

### 문제 발생 조건

- 직접 검증: 최초 ADD 실패, MOD 후 ADD 복구 실패, MOD 실패를 강제로 주입한 경우
- 각 실패 후 연결 매핑은 사라졌지만 fcntl(F_GETFD)로 소켓 잔존 확인
- 실제 운영 환경에서의 오류 발생 빈도와 자원 고갈 상황은 미검증

## 원인 및 해결

modify_epoll_events()가 closing을 먼저 설정해 정리 함수의 조기 반환을 유발했다. 실패 처리 3곳의 선행 설정을 제거해 공통 종료 함수가 플래그 설정과 close()를 수행하도록 변경했다.

## 해결 과정

### 1. 분석과 재현

**사용자 요청**

- epoll 실패 시 소켓 미종료의 실제 여부와 수정 필요성 검토 요청

**결과**

- 실패 처리의 closing 설정과 정리 함수의 조기 반환 충돌 확인
- 오류 주입으로 실패 경로 3곳의 소켓 잔존 재현 및 수정 필요 판정

### 2. 수정과 검증

**사용자 요청**

- 제시한 해결책 실행 요청

**결과**

- 실패 처리의 선행 closing 설정 3곳 제거
- 같은 실패 조건에서 연결 정보 삭제와 소켓 닫힘 확인

## 조언

- 오류 주입으로 확인한 처리 결함과 실제 오류 발생 빈도를 구분할 필요가 있음. 재현 성공만으로 운영 중 빈번한 장애라고 판단할 수 없음.

## 변경 파일

| 파일 | 변경 내용 |
|---|---|
| server/utils.cpp | epoll 실패 시 closing 선행 설정을 제거하고 정리 함수가 소켓을 닫도록 변경했다. |

## 확인 결과

- 기존 임시 재현 프로그램 재빌드 후 최초 ADD 실패, MOD 후 ADD 복구 실패, MOD 실패에서 소켓 닫힘과 연결 매핑 삭제 확인
- 오류는 epoll_ctl에 강제로 주입했으며 커널 자원 고갈 자체는 미재현
- server/에서 make 실행은 Makefile 부재로 실패했으나 기존 CMake 설정의 서버 빌드 통과
- 사용자 운영 환경의 해결 확인은 아직 없음
