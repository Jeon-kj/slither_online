# 잘못된 각도·부스트 JSON에 의한 서버 종료 방지

## 문제 요약

각도·부스트 메시지의 JSON 파싱 예외가 처리되지 않아 서버 프로세스가 종료될 수 있었음.
사용자가 실제 장애를 겪은 사례는 없으며, 코드 분석과 별도 실행으로 위험을 확인했음.

### 문제 발생 조건

- 수정 전 `MSG_ANGLE` 또는 `MSG_BOOST_STATUS` 처리에 문법이 잘못된 본문이나 잘못된 필드 타입 전달
- 직접 검증: 기존 메시지 처리 함수에 `{` 전달 시 미처리 `parse_error`로 검증 프로세스 종료
- 코드 확인: 네트워크 스레드까지 예외 처리 경계가 없어 실제 수신 경로에서도 프로세스 종료 가능
- 정상 Unity 클라이언트는 타입이 정해진 payload를 직렬화하며, 일반적인 각도 계산에서 `1e100`이 발생하는 상황은 아님

## 원인 및 해결

`json::parse`와 암시적 값 변환에서 발생하는 예외를 처리하지 않았음.
`handle_message`에 JSON 예외 처리 경계를 추가하고, 각 핸들러에서 객체·필드·타입을 검증했음.
각도는 double 상태에서 유한성과 float 표현 범위를 확인한 뒤 변환하도록 변경했음.
잘못된 메시지는 버리고 기존 상태를 유지하며, JSON 예외는 로그로 기록함.

## 해결 과정

### 1. 위험 판단과 방어 범위 결정

**사용자 요청**

- 잘못된 JSON에 의한 서버 종료 가능성이 실제 결함인지 검토하고 해결책 제시 요청
- 유한성 검사와 외부 입력 방어의 필요성 설명 후 수정 요청

**결과**

- 두 핸들러와 네트워크 스레드의 예외 전파 경로 확인
- 누락 필드·타입 오류·문법 오류의 예외 발생 및 큰 숫자의 float 변환 결과 확인
- 정상 클라이언트의 발생 가능성과 임의 입력에 의한 위험 구분
- 공통 JSON 예외 처리 및 두 입력의 기본 검증으로 수정 범위 한정
- 각도 제한을 게임상 각도 범위로 확장하지 않고 유한한 float 표현 범위로 설정

## 조언

- 비정상 입력을 개별 나열하기보다 허용할 필드와 타입을 정의하고, 공통 처리 경계에서 JSON 예외를 처리하는 방식 유지 권장

## 변경 파일

| 파일 | 변경 내용 |
|---|---|
| `server/message_handler.cpp` | 무검증 JSON 파싱·변환을 공통 예외 처리와 각도·부스트 입력 검증으로 변경했다. |

## 확인 결과

- 기존 메시지 처리 함수를 호출한 검증에서 수정 전 `{` 입력으로 프로세스 종료 확인(종료 코드 134)
- 동일 검증의 수정 후 실행에서 잘못된 메시지 24건의 상태 보존 및 정상 메시지 4건의 상태 갱신 확인
- 빈 본문, 잘못된 문법, 필드 누락, 객체가 아닌 JSON, null, 잘못된 타입, 양·음의 float 범위 초과, 파싱 숫자 범위 초과 확인
- 잘못된 메시지 처리 후 정상 각도·부스트 입력을 계속 처리함을 확인
- `server/`에서 `make` 실행 시 Makefile 부재로 실패했으며, 기존 CMake 빌드 디렉터리를 사용하는 `make -C build`로 서버 빌드 통과
- 실제 소켓 송수신 및 Unity 플레이 검증은 수행하지 않았음
- 해결 기록 가이드와 지정 참고 문서를 읽고 필수 제목·구분 문구 및 검증 한계 대조 완료
