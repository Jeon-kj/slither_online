# AI 활용 개발 회고

## 목표

사용자가 다음 방향으로 성장하도록 실제 작업을 평가한다.

1. AI에 의존하지 않고 활용할 줄 아는 개발자
2. 차별성을 가진 인재가 될 수 있는 활용법과 사고를 갖춘 개발자
3. 중요한 변경의 성공 기준과 검증 방법을 이해하고,
   결과를 받아들일지 판단할 수 있는 개발자

## 리뷰의 중심

- 주된 평가 대상은 사용자의 요청, 위임 범위, 개입, 결과 수용 방식이다.
- 각 핵심 요청을 기준으로 다음을 평가한다.
  1. 문제와 원하는 결과를 충분히 전달했는가?
  2. AI에게 맡긴 판단과 실행의 범위가 적절했는가?
  3. 결과를 판단하는 데 필요한 근거를 요구했는가?
  4. 더 효율적인 활용 방식이 있었는가?
- AI의 실수는 사용자의 활용 방식을 평가하는 데 필요한 경우에만 다룬다.
  AI 작업 품질 회고로 리뷰를 대체하지 않는다.
- 사용자가 검토할 요청을 지정했다면 그 요청을 중심으로 평가한다.
  이후 문서 수정이나 리뷰 대화로 평가 범위를 확장하지 않는다.

## 검토 범위

- 현재 대화에서 지정한 문제의 요청, 분석, 수정, 검증, 수용 과정을 검토한다.
- 필요한 경우 해당 변경의 코드와 작업 기록을 확인한다.
- 사용자와 AI가 실제로 수행한 일을 근거에 맞게 기록한다.
- 대화가 누락됐거나 근거가 부족하면 평가 가능한 범위를 명시한다.

## 평가할 질문

### 문제 이해와 판단

- 사용자가 증상, 발생 조건, 기대 동작을 충분히 전달했는가?
- 관찰과 추측을 구분하고, 새 근거에 따라 판단을 바꿨는가?
- 근거 없이 원인을 단정하거나 후보를 제외한 부분이 있는가?
- 중요한 선택에서 효과와 비용을 이해하고 수용한 근거가 있는가?
- AI가 사용자의 추측에 무비판적으로 동조하거나 근거 없는 결론을 냈는가?

### 검증과 결과 수용

- 중요한 변경에 성공 기준이 있었는가?
  기준을 AI가 제안했다면 실제 목표에 맞는지 검토됐는가?
- 검증이 원래 발생 조건과 실패 상황을 실제로 다뤘는가?
- 코드 검토, 수치 모델, 실제 실행 결과를 구분했는가?
- 성공 보고를 받아들일 근거가 충분한가?
- 확인하지 못한 부분이 결과 수용에 얼마나 중요한가?

### 학습과 다른 문제에 적용할 능력

- 이번 변경에서 사용자가 이해해야 할 핵심 원리나 코드 경로는 무엇인가?
- 대화에서 확인된 이해와 아직 확인되지 않은 이해는 무엇인가?
- 조건이 달라져도 판단하는 데 필요한 지식이 빠져 있는가?
- 사용자의 진로와 이번 작업의 중요도를 고려할 때,
  추가로 살펴볼 가치가 가장 큰 부분은 무엇인가?

### 활용 방식과 차별성

- AI에 위임한 범위와 사용자 개입이 작업 목적에 적절했는가?
- 반복 질문, 불필요한 승인, 과도한 검증이나 문서화로 낭비한 부분이 있는가?
- 사용자의 관찰·선택·검증·환경 구성이 결과에 어떤 영향을 주었는가?
- 실제로 반복된 막힘 중 지침, 도구, 검증 환경으로 개선할 부분이 있는가?
- 이번 경험으로 보여줄 수 있는 기본 역량과 차별성 후보는 무엇인가?
  차별성 주장을 뒷받침할 실제 결과가 있는가?

## 의존도 판단

- 분석·구현·테스트를 넓게 위임했다는 사실만으로 의존적이라고 판단하지 않는다.
- 다음을 구분한다.
  - 실행의 위임: 코드 작성, 도구 실행, 반복 시험 등을 맡기는 것
  - 판단의 위임: 원인 확정, 성공 기준, 변경 영향, 결과 수용을
    근거 확인 없이 AI에게 맡기는 것
- 사용자가 중요한 판단을 검토한 근거가 있는지 평가한다.
- 대화에서 이해가 드러나지 않았다면 ‘확인되지 않음’으로 적는다.
  이해 부족이나 무비판적 수용으로 단정하지 않는다.

## 평가 원칙

- AI에 분석·구현·테스트를 넓게 맡길 수 있다.
  위임의 적절성과 사용자가 보여준 역량은 각각 판단한다.
- 직접 작성한 코드량이나 질문 횟수를 역량의 기준으로 삼지 않는다.
- AI가 수행한 분석과 판단을 사용자의 역량으로 귀속하지 않는다.
- 사용자가 설명하지 않은 내용을 곧바로 이해하지 못한다고 판단하지 않는다.
  중요한 이해가 확인되지 않았다면, 확인할 질문이나 코드 지점을 구체적으로 제시한다.
- 코드 확인은 핵심 동작, 검증의 타당성, 중요한 변경 영향을 이해하는 데 필요한 범위로 제안한다.
- 테스트를 통과했거나 증상이 사라졌다는 사실만으로 원인 규명과 사용자 이해까지 인정하지 않는다.
- 평범한 요청이나 기본 검증을 차별성으로 과장하지 않는다.
  실제 선택과 결과에 근거해 설명한다.
- 개선 제안은 정확성, 효율, 판단력, 학습 중 무엇을 개선하는지 밝힌다.
- 충분했던 부분은 충분했다고 평가한다. 비판이나 칭찬을 억지로 만들지 않는다.
- 회고 결과는 대화로 제공한다. 파일 저장은 사용자가 요청할 때 수행한다.

## 출력

중복을 줄여 다음 순서로 짧게 작성한다.

1. 사용자의 AI 활용 방식에 대한 전체 평가를 짧게 제시한다.

2. 핵심 요청별로 다음을 설명한다.
   - 충분했던 점
   - 위임 범위와 의존도 평가
   - 개선할 가치가 있을 때만 더 나은 요청·행동과 그 효과

3. 결과 수용에 필요한 사용자 이해 중 확인된 것과 미확인된 것을 구분한다.

4. 다음 작업에 적용할 활용 원칙 하나를 제안한다.

AI의 실수 목록, 코드 변경 요약, 학습 질문 목록으로 요청별 평가를 대신하지 않는다.

  가이드가 지정한 참고본을 모두 읽는다. 가이드의 필수 구성과 구분 문구를 유지한다.
- 작성 후 실제 문서를 가이드의 확인 항목과 대조한다.
